# 03. 汇编器与字节码格式（JadeightAbstractionCode）

本文档描述 Jadeight 生态的**汇编层**（`JadeightAbstractionCode`）：它把人类可读的 **jasm 汇编文本**
汇编为 Jadeight2 虚拟机直接执行的 **`.bc` 模块文件**。核心是一个 header-only 的 C++ 库
`jadeight_asm.hpp`（含 `Assembler` 类 = 汇编器 + 反汇编器），被两个使用者复用：独立的命令行工具
`jasm` / `jasm_dbg`，以及 j8c 编译器（`JadeightCompiler` 内嵌调用）。

> **唯一事实来源**：ISA v3 的 opcode 枚举、助记名表（`opName`）、指令长度表、模块格式
> （`ModuleImage`）、编码器（`Asm`）全在 `Jadeight2ReWrite/isa.hpp`。本层**不再自带一份助记名表**
> （v2 汇编器抄过一份，改指令集时两边容易漂）。逐条指令的语义、TD 位域、v2→v3 对照见
> [06-指令集参考.md](06-指令集参考.md)，本文只讲"怎么汇编 / 编出来长什么样"。

---

## 1. 定位与作用

```
        jasm 汇编文本（.jasm / .asm）
                    │
        jadeight_asm.hpp :: Assembler
        （单趟发射 + pending 回填标签/函数名 → 生成函数目录 → 定入口函数）
                    │
              .bc 模块文件（ISA v3）
        （magic "J3BC" + 版本 + 函数目录 + 连续码流，全小端）
                    │
        Jadeight2 虚拟机执行（解释器 / copy-and-patch 模板 JIT）
```

- **汇编器本体**：`jadeight_asm.hpp`，约 700 行，header-only、无外部依赖（仅标准库 + `isa.hpp`），C++20。
- **两种使用方式**：
  1. **独立 CLI**：`main.cpp`（编译产物 `jasm`、带调试信息的 `jasm_dbg`）——手动汇编/反汇编 `.asm` ↔ `.bc`；
  2. **库方式内嵌**：`JadeightCompiler`（j8c）`#include "jadeight_asm.hpp"`，在代码生成阶段直接调用
     `Assembler::assembleModule()`（经 `assemble()` 包装），把编译器生成的 jasm 文本当场汇编成字节码，
     无需外部进程。
- **与 VM 的关系**：本层的 opcode 编号、指令编码、指令长度全部来自 `isa.hpp`；VM
  （`Jadeight2ReWrite/Jadeight2.cpp`）与模板 JIT（`jit.hpp`）也从同一份 `isa.hpp` 取长度表与名称表，
  因此三方逐字节一致。
- **与 v2 的差别（一句话）**：v2 是「类型焊死在 opcode 里的展开式指令集、12 字节文件头 + 指令流 BE、单函数」；
  v3 是「**68 条 opcode + 类型操作数 TD** + "J3BC" 模块 + 多函数 + 标签跳转」，操作数**一律小端（LE）**。

## 2. 源码结构与构建

目录结构：

```
JadeightAbstractionCode/
├── jadeight_asm.hpp      # 核心：Assembler 类（汇编 + 反汇编）
├── main.cpp              # jasm 命令行薄入口（解析参数、读写文件、调 Assembler）
├── jasm.cpp              # 与 main.cpp 内容几乎相同（仅失败报错一行有差异），保留其一即可
├── CMakeLists.txt        # add_executable(jasm main.cpp)，C++20，include ../Jadeight2ReWrite
├── jasm                  # 编译好的 CLI（ELF x86-64，动态链接，无调试信息）
└── jasm_dbg              # 同一 CLI 的调试构建（带 debug_info，体积更大）
```

`CMakeLists.txt`（全文）：

```cmake
cmake_minimum_required(VERSION 3.22)
project(JadeightAbstractionCode CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# jasm：ISA v3 汇编器 / 反汇编器（main.cpp 与 jasm.cpp 内容相同，取其一）
# isa.hpp（ISA v3 定义）在 Jadeight2ReWrite 下
add_executable(jasm main.cpp)
target_include_directories(jasm PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/../Jadeight2ReWrite)
target_compile_options(jasm PRIVATE -Wall -Wextra -Wno-unused-parameter)
```

手工编译：

```bash
g++ -std=c++20 -O2 main.cpp -I../Jadeight2ReWrite -o jasm
```

> 注意：`main.cpp` 顶部的注释块仍是 v2 遗留字样（把 opcode 条数写成 v2 展开后的数量、把 `-e` 描述成
> "默认大端头"）。
> **以源码行为为准**：实际汇编器是 ISA v3，输出一律小端，`-e` 已无实际作用（见第 6 节）。
> 若要手工构建，必须把 `../Jadeight2ReWrite` 加进头文件搜索路径（`main.cpp` 靠它找到 `isa.hpp`）。

## 3. 汇编 API（jadeight_asm.hpp）

全部符号位于 `namespace jadeight`。

### 3.1 助记名与操作数解析

| 符号 | 作用 |
|---|---|
| `bool mnemonicToOp(const std::string&, uint8_t& op)` | 助记名 → opcode。内部持一份 68 条 opcode 的 `known[]` 数组，**逐个与 `isa.hpp` 的 `opName(k)` 比对**；因此名称表的唯一副本在 `isa.hpp`，本层只负责遍历。名称**区分大小写**（必须大写）。 |
| `bool tdFromName(const std::string&, uint8_t& td)` | 类型操作数名 → TD：`u8 u16 u32 u64 i8 i16 i32 i64 f32 f64 ptr`（全小写）。 |
| `bool cmpFromName(const std::string&, uint8_t& sub)` | `CMP` 的子操作名 → 子码：`LT LE EQ NE GT GE`（全大写）。 |
| `bool parseU64(const std::string&, uint64_t&)` | 数值解析：十进制、`0x` 十六进制、带 `+/-` 的数（`strtoll` base 0，负数按二进制补码存）、字符字面量 `'A'`。**不支持转义序列**：`'\n'` 取的是第二个字符 `\`（=92）。 |
| `bool parseReg(const std::string&, uint8_t&)` | 寄存器解析：`R0`~`R15`（`R`/`r` 均可，值须 ≤15）。 |
| `std::vector<AsmLine> parseAsmLines(const std::string&)` | 词法：按行切成 `{label, directive, mnemonic, args, raw}`。 |
| `struct AsmLine` | 一行汇编的中间表示：标签、伪指令（`.FUNC` 等，含点）、助记名、参数列表、原始行文本。 |
| `void asmLoadRaw(const uint8_t*, uint8_t w)` | 反汇编时按宽度小端读回立即数。 |

### 3.2 Assembler 类

```cpp
class Assembler {
public:
    bool verbose = false;             // -v：逐条打印 "  [偏移] 原文 (字节数)"
    bool pureBinary = false;          // true：assemble() 只输出纯码流（j8c 内部用），不带模块头
    bool littleEndianHeader = true;   // v2 兼容开关；v3 一律小端，assemble/disassemble 都不读它
    std::vector<ModuleFunc> funcs;    // 汇编产物：函数目录（isa.hpp 的 ModuleFunc）
    std::string inputPath, outputPath;// 仅供 CLI 记录用
    std::string error;                // 最近一次失败原因

    bool assemble(const std::string& asmText, std::vector<uint8_t>& outBytes,
                  uint32_t& argSize, uint32_t& retSize, uint32_t& entry);
    bool assembleModule(const std::string& asmText, ModuleImage& img);
    bool disassemble(const std::vector<uint8_t>& bytes, std::ostream& os, bool hasHeader);
};
```

- **`assemble()`** 是 `assembleModule()` 的兼容包装：`pureBinary ? img.code : img.serialize()`，
  并把**入口函数**的 `argSize/retSize/entry` 回填给旧的三个输出参数（j8c 仍按这个签名调用）。
- **`assembleModule()`** 是真正的汇编入口，产出完整 `ModuleImage`（函数目录 + 码流 + `entryFunc`）。
- **`funcs`** 在每次 `assembleModule()` 后被同步成 `img.funcs`——j8c 就是靠它拿函数目录的。

### 3.3 汇编流水线（assembleModule）

1. `parseAsmLines`：逐行去掉 `;` 与 `//` 之后的内容，按空格/制表符/逗号切词；首个词以 `.` 开头视为伪指令，否则视为助记名。若还没有函数，遇到第一条指令/标签会**隐式开一个 `main` 函数**。
2. **单趟发射**：查助记名 → 写 opcode 与各操作数；跳转目标、`CALL` 的函数名、`JIT_SUBMIT`/`FUNC_ADDR`/`THREAD_SPAWN`/`PROC_SPAWN` 的函数名先占位写 0，记进 `pending` 列表。
3. **第二趟回填**：标签查**本函数内**的 `std::map`（标签值是"函数相对偏移"），函数名查全局 `funcIndex`；未定义报 `未知标签: X` / `未知函数: X`。
4. **函数目录**：`ModuleFunc{offset, size, argSize, retSize, entry}`，`size` 由下一个函数起点（末函数取码流总长）算出，`entry = offset`。
5. **入口函数**：见下方 `.ENTRY` 规则；`argSize/retSize/entry` 取入口函数的那一份。
6. **伪指令 `.BYTE/.FILL` 直接写进码流**，汇编器不为它们建标签之外的任何结构——跳到数据区是允许的，语义自负。

> 报错示例（`error` 字段）：`未知指令: add`、`未知伪指令: ...`、`未知标签: nope`、`未知函数: f`、
> `非法类型: ?`、`非法寄存器: R99`、`指令缺少/非法操作数: CALL 需要 func, argOff, retOff (...)`。
> 注意：**多余的操作数被静默忽略**（v2 那种 "does not take operands" 报错已不存在），例如
> `ADD u64 7` 等同于 `ADD u64`。

### 3.4 反汇编

`disassemble(bytes, os, hasHeader)`：

- `hasHeader=true` 且字节数 ≥20 且以 `J3`（`J3BC`）开头 → 按 v3 模块头 `deserialize`，逐函数反汇编；
  否则把整段字节当**单函数纯码流**处理（`-f` 走的就是这条路）。
- 每个函数先打印一行注释 `; .FUNC fnN argSize=.. retSize=.. offset=.. size=.. entry=..`，
  再打印可汇编的 `.FUNC fnN <参数字节> <返回字节>`。
- 每条指令前打印 **`L<函数内偏移>:` 标签**（如 `L9:`、`L35:`），跳转目标也按同样规则打印；
  因此反汇编文本**可以再次汇编**（函数名会退化成 `fn0`/`fn1`…，标签名会重排，但字节码等价）。
- 未知 opcode 打印 `.BYTE <十进制值>`；**注意**：若数据区被当代码解码，遇到"opcode 合法但 TD 非法"的情形会打印成
  `SQRT ?` 这种带 `?` 的行，这种文本**无法再汇编**（`非法类型: ?`）。

### 3.5 j8c 如何调用它

`JadeightCompiler/CMakeLists.txt` 定义 `JADEIGHT_VM_DIR=${CMAKE_CURRENT_SOURCE_DIR}/../Jadeight2ReWrite`
并把两个目录都加进头文件搜索路径；`src/driver.cpp` `#include "jadeight_asm.hpp"`。

实际汇编发生在 `src/codegen.cpp` 的 `CodeGen::generate` 末尾：

```cpp
// 生成 jasm 文本后内嵌汇编：纯码流，函数目录从 asmblr.funcs 取
Assembler asmblr;
asmblr.pureBinary = true;
uint32_t as_, rs, en;
if (!asmblr.assemble(asmText, outBytes, as_, rs, en)) { /* 报错并 dump asmText */ }
// 尺寸必须与编译期按标签/长度预测的一致（偏移正确性的强保证）
```

生成的 jasm 文本形如 `.ENTRY <绝对偏移>` + 每个函数 `.FUNC <名> <参数字节> <返回字节>`
+ 数据段单独划的 `.FUNC __data 0 0`。随后 `driver.cpp` 自己拼模块：

```cpp
jadeight::ModuleImage img;
img.entryFunc = cg.entryFuncIndex;   // 由 .ENTRY 的绝对偏移落进哪个函数区间算出
img.funcs = cg.moduleFuncs;
img.code  = bc;
const std::vector<uint8_t> bytes = img.serialize();   // magic "J3BC" + 目录 + 码流
```

加 `-S` 时 j8c 另存 `.jasm` 供人查看。`JadeightCompiler/tools/*` 也 `#include "jadeight_asm.hpp"`
复用同一套编码/长度表。

> 遗留字样：`driver.cpp` 的 `-v` 结束语仍按 v2 算式打印 `(12 + bc.size()) 字节`，而 v3 模块的真实大小是
> `20 + 20 × 函数数 + codeSize`（例如 t2_control：打印 6485，实际 6733）。

## 4. jasm 汇编文本格式

### 4.1 词法

- **注释**：`;` 或 `//` 到行尾（两者等价，先掐掉再解析）。
- **操作数分隔**：空格 / 制表符 / 逗号均可（`, ` 与空格等价，与反汇编输出格式一致，便于回环）。
- **助记名大小写敏感**：必须大写（`add u64` 会报 `未知指令: add`）。
  类型名小写（`u8`/`ptr`），`CMP` 的子操作大写（`LT`）；寄存器 `R0`/`r0` 都行。
- **数值**：十进制、`0x` 十六进制；带 `+/-` 的数走 base 0（`-1` 存成补码）；字符字面量 `'A'`。
  不支持 `'\n'` 这类转义（会取到 `\`）。
- **寄存器**：`R0`~`R15`（16 个 64 位寄存器；编码时只取低 4 位）。

### 4.2 函数、标签与跳转

- **函数**用 `.FUNC` 划分；**标签**是"裸名 + 冒号"，可独占一行也可与指令同行（`L1: NOP`）。
- 标签作用域是**函数内**：重名不报错（后写覆盖前写，引用取最后一次的偏移）；未定义则报
  `未知标签`。函数名（`.FUNC` 的第一个参数）是**全局**的，供 `CALL`/`FUNC_ADDR`/`JIT_SUBMIT`/
  `THREAD_SPAWN`/`PROC_SPAWN` 按名引用，也供 `.ENTRY` 按名指定。
- **跳转只有标签跳转**：`JMP L1` / `BRANCH L1`，操作数是**函数相对偏移**（相对本函数入口），
  函数在模块内位置无关、模块可整体重定位；没有 PC 相对跳转，也没有"跳转必须写绝对数字"这回事
  （写数字仍被接受，按函数相对偏移解释）。

### 4.3 伪指令

| 伪指令 | 语法 | 作用 |
|---|---|---|
| `.FUNC` | `.FUNC <名> [参数字节] [返回字节]` | 划分函数：记下起点，登记函数名，产出目录项；后续指令/标签都归它。参数/返回字节缺省为 0 |
| `.ENTRY` | `.ENTRY <函数名 \| 数字>` | 指定入口函数。数字 **< 函数个数**时当**函数下标**；否则当**码流绝对偏移**，换算成包含它的函数下标；都不匹配则回退 0 |
| `.ARGS` / `.RETS` | `.ARGS n` / `.RETS n` | v2 遗留：只对**单函数模块**（隐式/唯一的 `main`）生效，写入该函数的 `argSize/retSize` |
| `.STACK` / `.SCOPE` | `.STACK n` / `.SCOPE n` | 接受并忽略（栈由运行时 `STACK_INIT` 决定） |
| `.BYTE` | `.BYTE v1 v2 ...` | 逐字节原样发射（取低 8 位） |
| `.FILL` | `.FILL count, [value]` | 连续发射 `count` 个 `value`（缺省 0）字节 |

> 函数目录项的 `entry` **恒等于函数起点 `offset`**：汇编器目前不支持"函数内非零入口偏移"，
> `.ENTRY <函数内的标签>` 只用于选函数（落到该标签所在函数），不会把入口设成标签偏移。
> `.BYTE/.FILL` 嵌进码流后与指令无法区分（反汇编的固有限制，见 3.4）。

### 4.4 指令书写形式

v3 的书写形式是**「助记名 + 类型操作数」**，类型写在最前面（少数除外）：

```asm
; 无操作数 / 无类型：控制流、栈、作用域、系统
NOP / HALT / RET / TRAP / SCOPE_PUSH / SCOPE_POP / GET_ADDRS / GET_SYSTEM
BRANCH L1                 ; u32 标签（函数相对）
JMP L2                    ; u32 标签
JMP_IND                   ; 弹栈取绝对地址（FUNC_ADDR 压入）

; 带类型（TD 是紧跟在 opcode 后的第一个参数字节）
ADD u8                    ; 算术：ADD/SUB/MUL/DIV/REM/NEG，位运算 SHL/SHR/AND/OR/XOR/NOT
SQRT f64                  ; 数学：SQRT/LOG（结果一律压 f64）
COUT u8                   ; u8 按字符打印，其余按数值/浮点
MOVI u64 R0, 123          ; 立即数 → 寄存器（宽度由 TD 决定）
PUSH_IMM u64 42           ; 立即数 → 数据栈
PUSH_REG u64 R0 / POP_REG u32 R3
LOAD u64 R0, 0, 40        ; td, reg, mode(0|1), off:u32
STORE u64 R1, 1, 8
LEA 1, 16                 ; mode, off:u32 → 压地址
ATOMIC_ADD u64 R0, 1, 8   ; 原子（td 只允许 4/8 字节整数）
CMP LT u32                ; 子操作 + 类型；LT/LE/EQ/NE/GT/GE，结果压 u8
CVT i32, f64              ; 源类型, 目标类型

; 无类型的寄存器/函数/系统指令
MOV R1, R0                ; dst, src（注意：MOV 不带 TD）
CALL 1, 0, 8              ; 函数下标（或函数名）, argBaseOff, retOff
CALL_IND R5, 8, 0         ; reg, argBaseOff, retOff（目标是字节码绝对地址）
CALL_NATIVE R5, 8, 0      ; reg, argBaseOff, retOff（目标是原生入口）
FUNC_ADDR 1               ; 函数下标（或函数名）→ 压入口绝对地址
JIT_SUBMIT 1, 0           ; 函数下标（或函数名）, outOff → 编译并写回原生指针
JIT_COMPILE 40, 48, 56    ; ptrOff, lenOff, outOff：编译任意一段字节码
STACK_INIT 1024 256       ; size, scopeSize
STACK_MOVE 16 / STACK_ALLOC 4096
NEW_HEAP 0, 1024 / DEL_HEAP 0
NEW_ARRAY 64, 8 / FREE_ARRAY 8
MEMCPY 0, 128, 1, 0, 64   ; dstMode, dstOff, srcMode, srcOff, size
EXTERN_CALL 3, 16, 32     ; idx, argBase, retOff
DL_REG 0, 8, 16 / DL_CALL 0, 8, 16
THREAD_SPAWN 2, 0, 16 / THREAD_JOIN 16 / THREAD_EXIT / THREAD_SELF 16 / THREAD_YIELD
PROC_SPAWN 2, 0 / PROC_WAIT 0, 8 / PROC_EXIT / PROC_SELF 8 / PROC_SHARE 4096, 16
```

> `mode`（0/1）：mode0 直接读写 `Stack[作用域基址 + off]`（栈槽寻址）；mode1 先从该栈槽弹/读一个指针再解引用。
> 各指令的完整语义、TD 位域与"sign 什么时候才生效"见 [06-指令集参考.md](06-指令集参考.md)。

### 4.5 完整示例（可汇编、可反汇编回环）

```asm
; example.asm —— 两个函数 + 标签跳转 + 一条数据区指令
.FUNC main 0 0
    STACK_INIT 1024 128
    MOVI u64 R0, 123
    PUSH_IMM u64 42
    MOV R1, R0
    LOAD u64 R0, 0, 40
    STORE u64 R1, 1, 8
    ADD u8
    CMP LT u32
    BRANCH L1
    JMP L2
L1:
    CALL add42, 0, 8        ; 按函数名调用
    JIT_SUBMIT add42, 16    ; 把该函数即时编译，指针写回栈槽 16
L2:
    HALT

.FUNC add42 8 8
    STACK_INIT 256 32
    RET
.ENTRY main
```

```bash
./jasm example.asm -o example.bc -v    # 汇编（-v 逐条打印偏移与字节数）
./jasm example.bc -d                   # 反汇编回文本
```

## 5. 字节码 .bc 文件格式（ISA v3 模块）

### 5.1 文件布局（全小端）

```
┌──────────────────────────────────────────────────────────┐
│ [0..4)    magic "J3BC"                                   │
│ [4..8)    u32 version = 3                                │
│ [8..12)   u32 funcCount                                  │
│ [12..16)  u32 codeSize                                   │
│ [16..20)  u32 entryFunc（入口函数下标，不一定是 0）        │
├──────────────────────────────────────────────────────────┤
│ funcCount × 20 字节 函数目录：                             │
│   { offset:u32, size:u32, argSize:u32, retSize:u32, entry:u32 } │
├──────────────────────────────────────────────────────────┤
│ codeSize 字节码流（函数首尾相接；操作数一律小端）           │
└──────────────────────────────────────────────────────────┘
```

- **所有字段一律小端**：没有"头部字节序"这个开关了，也没有指令内部的 BE 操作数——v2 的
  "12 字节头 LE + 指令流 BE"混搭到此结束，`serialize()` 直接 `putU32` 小端逐字段写出。
- **`entry` 是函数内的入口偏移**（相对 `offset`）；汇编器产出的目录项里它恒等于 `offset`。
- **跳转标签是函数相对**的，所以函数在模块内位置无关，整个模块可以重定位。
- 反序列化 `ModuleImage::deserialize()` 会校验 magic、版本必须 =3、`20 + 20×funcCount + codeSize ≤ 文件长度`。

实测（4.5 节示例的精简版：单函数、入口 0）hexdump：

### 5.2 指令编码与长度

每条指令 = 1 字节 opcode + 定长操作数；**类型化指令的第二个字节是 TD**；`MOVI`/`PUSH_IMM` 的立即数
按 TD 的字节数（1/2/4/8）跟在后面。汇编器与 JIT、j8c 共用 `isa.hpp` 的
`instrLen(const uint8_t*)`（线性扫描）与 `opLenFixed(uint8_t)`（不含立即数本身的"骨架长度"）。

| 长度 | 指令 |
|---|---|
| 1 | `TRAP` `NOP` `HALT` `RET` `JMP_IND` `SCOPE_PUSH` `SCOPE_POP` `GET_ADDRS` `GET_SYSTEM` `THREAD_EXIT` `THREAD_YIELD` `PROC_EXIT` |
| 2 | 15 条带 TD 的栈机指令：`ADD` `SUB` `MUL` `DIV` `REM` `NEG` `SHL` `SHR` `AND` `OR` `XOR` `NOT` `SQRT` `LOG` `COUT` |
| 3 | `MOV`(dst,src) `PUSH_REG`(td,reg) `POP_REG`(td,reg) `CMP`(sub,td) `CVT`(srcTd,dstTd) `FUNC_ADDR`(u16) |
| 3 + tdBytes | `MOVI`（td, reg, imm） |
| 2 + tdBytes | `PUSH_IMM`（td, imm） |
| 5 | `JMP` `BRANCH`（u32 标签） `STACK_MOVE` `DEL_HEAP` `FREE_ARRAY` `THREAD_JOIN` `THREAD_SELF` `PROC_SELF` |
| 6 | `LEA`（mode u8 + off u32） |
| 7 | `JIT_SUBMIT`（fn u16 + outOff u32） `PROC_SPAWN`（funcIdx u16 + argOff u32） |
| 8 | `LOAD` `STORE` `ATOMIC_LOAD/STORE/XCHG/CAS/ADD`（td,reg,mode,off u32） |
| 9 | `STACK_INIT`（u32+u32） `STACK_ALLOC`（u64） `PROC_WAIT`（u32+u32） |
| 10 | `CALL_IND` `CALL_NATIVE`（reg + u32 + u32） `EXTERN_CALL`（u8 + u32 + u32） |
| 11 | `CALL` `THREAD_SPAWN`（u16 + u32 + u32） |
| 13 | `NEW_HEAP` `NEW_ARRAY` `DL_REG` `DL_CALL` `PROC_SHARE` `JIT_COMPILE` |
| 27 | `MEMCPY`（mode u8 + off u64 + mode u8 + off u64 + size u64） |

非法/未知 opcode 在 `instrLen` 里返回 0；反汇编遇到**未知 opcode、非法 TD 字节、越界 CMP 子操作数、
被函数尾截断的指令、或指向不存在标签的跳转**时，会把该行退化成按字节的 `.BYTE`（保证回环，见 5.4）。

> ⚠️ 这两张长度表必须等于 `Asm` 编码器真正写出的字节数。曾出现 `OP_PROC_SPAWN` 与 `OP_LEA`
> 合并成 6 字节的错误（实为 7），会让含该指令的函数在 JIT 预扫时整体错位；现已修复，
> 并由 VM 自测「ISA 长度表与编码器逐条一致」（64 条带编码器的指令）常驻看护。

### 5.3 加载与兼容性

`Jadeight2ReWrite/Jadeight2.cpp` 的 `save` 就是模块容器：

```cpp
bool loadFromFile(const char* path) {          // 读整个文件
    ModuleImage img;
    if (!img.deserialize(buf.data(), buf.size())) return false;  // 认 magic/版本/长度
    return loadImage(img);
}
```

- `loadImage()` 把目录拷进 `save::funcs`，把 `code` 拷进 `build`，再 `freeze()`：mmap 页对齐 +
  **末尾追加 3 个 `OP_TRAP` 哨兵** + `mprotect(PROT_READ)` 冻结为只读。
- **哨兵不进文件**：文件只有 `codeSize` 字节码，3 个 `OP_TRAP` 是 VM 装载时补的，供取指越界安全退出。
- `entryFunc` 也从模块头带进 `save::entryFunc`（j8run 用它决定入口）。
- **兼容性**：
  - `jasm` 产出的 `.bc` 与 j8c 产出的 `.bc` 是同一格式，都能被 VM/`j8run` 直接加载；
  - **v2 的旧 .bc（12 字节 `argSize/retSize/entry` 头 + 指令流 BE）不是 v3 模块**，`deserialize()`
    会在 magic 处失败；`j8run` 的报错是 `j8run: cannot load v3 module: <path>`。
  - `JadeightPoject/byteCode/*.bc` 已刷新为 **v3 示例**：由 `j8c` 从
    `JadeightCompiler/tests/t2..t9` 重新生成（9 个用例里除 `t10_atomic` 需要
    `--threads 4` 之外全部入选），文件头都是 `J3BC`，`./run.sh` 直接可跑（实测 8/8 成功）。
    历史上那批 v2 遗留产物（`t1_basic.bc`、`dl_test.bc`、`final.bc` 等）只能喂给旧的
    `Jadeight2`（v2）VM，已移出该目录。

### 5.4 汇编 → 反汇编 → 再汇编（回环）

**不变式：任意 v3 模块经 `jasm -d` 反汇编后，都能被 `jasm` 原样再汇编回逐字节相同的 `.bc`。**

```bash
./jasm example.asm -o a.bc
./jasm a.bc -d -o a.jasm
./jasm a.jasm -o b.bc
cmp a.bc b.bc        # 一致
```

实现这一点的三条规则：

1. **反汇编会输出 `.ENTRY fn<入口函数下标>`**（文件首行）。反汇编给函数统一起名 `fn0`/`fn1`…，
   `.ENTRY` 按名引用，所以 `entryFunc != 0` 的情形（j8c 的 `main` 常常不是 0 号函数）也能还原；
   每行行首打印 `L<函数内偏移>:` 标签，`JMP`/`BRANCH` 按标签写回。
2. **无法精确还原的行退化成 `.BYTE`**。码流里可能夹着**数据**（j8c 把字符串常量以 `.BYTE`
   直接写进函数体，还会生成一个 `.FUNC __data`），线性扫描会把数据字节当指令解码；一旦出现
   「未知 TD 字节 / 越界 `CMP` 子操作数 / 被函数尾截断 / 跳转目标标签不存在」，该行就按字节
   输出 `.BYTE`，字节流因此原样保留。修复前这类行会输出 `SQRT ?` 这样的文本，而 `?` 不是
   合法类型，**再汇编直接失败**。
3. **标签与字节位置解耦**：把一行拆成若干 `.BYTE` 只改文本、不改各行起始偏移，所以行首标签
   仍然落在原位置，跳转不受影响。

回归测试：`JadeightAbstractionCode/tests/roundtrip.sh`（当前 **19/19**）覆盖两类输入——
手写夹具 `tests/data_in_code.jasm`（函数体里夹着字符串数据，复现过 `SQRT ?` 断裂）与
`JadeightCompiler/tests/*.j8` 经 `j8c` 直出的 9 个模块 × `-O0/-O2`。

## 6. jasm / jasm_dbg 可执行文件

两者是同一个 CLI（`main.cpp`）的两种构建；`jasm_dbg` 带调试信息供 gdb 调试。用法（实测运行输出）：

```
Usage: ./jasm input.asm [-o output.bc] [-d] [-v] [-f] [-e]
```

| 选项 | 含义 |
|---|---|
| `input.asm` | 汇编输入（必须）；默认输出同名前缀 `.bc` |
| `-o output.bc` | 指定输出文件（汇编模式写模块；反汇编模式可写文本清单） |
| `-d` | **反汇编模式**：输入是 `.bc`，输出可读指令清单（到 stdout 或 `-o` 文件） |
| `-v` | 详细输出：逐条打印 `[偏移] 原文 (字节数)`、结果统计（反汇编模式则是逐条调试信息） |
| `-f` | 输出**纯码流**（不带 v3 模块头；反汇编模式则按无头单函数码流处理） |
| `-e` / `--le` | **v2 遗留选项，v3 无实际作用**：v3 一律小端。实测带 `-e` 与不带 `-e` 产出的字节完全相同；它只影响 `-v` 结尾打印的字样（`Header (BE)` / `Header (LE)`） |

示例：

```bash
./jasm hello.asm                    # hello.asm -> hello.bc（v3 模块）
./jasm hello.asm -o out.bc -v       # 详细输出
./jasm out.bc -d                    # 反汇编
./jasm out.bc -d -o out.jasm        # 反汇编结果写文件（可再汇编回去）
./jasm raw.bin -d -f                # 无头字节流反汇编
```

注意：`-d` 对**非 v3 文件**（比如 v2 的 .bc）不会报错，而是把整段当成单函数码流解码——文件头会
显示成几条 `TRAP`/垃圾指令。若输入是 v3 模块，`-d` 会自动识别 `J3BC` 并按函数目录反汇编。

## 7. 与生态的关系

```
   j8c（JadeightCompiler）                 jasm（本层 CLI）
   .j8 源码 ──词法/语法/语义/优化──> jasm 文本   手写 .jasm 文本
        │  CodeGen::generate                          │
        │  （内嵌 Assembler，pureBinary）              │  ./jasm
        ▼                                              ▼
   .bc（v3 模块：J3BC + 函数目录 + 码流，全 LE）
        │
        ▼
   Jadeight2 虚拟机（02-Jadeight2虚拟机.md / Jadeight2ReWrite）
   save::loadFromFile → 解释器 execute() 逐条执行
   └─ 可选：JIT_SUBMIT / JIT_COMPILE / VM::jitCompile → copy-and-patch 模板 JIT 原生码
```

- **承接**：j8c（见 [04-j8c编译器.md](04-j8c编译器.md)）把 IR 发射成 jasm 文本（`.ENTRY` +
  每个函数一条 `.FUNC` + 数据段），再内嵌调用本层 `Assembler`（`pureBinary`）拿到码流与函数目录，
  最后用 `ModuleImage::serialize()` 写模块。`-S` 保留的 `.jasm` 就是这一中间文本，可交给 `jasm`
  手工再汇编。
- **产出**：`.bc` 被 Jadeight2（ISA v3）消费——`save::loadFromFile` 加载后由解释器执行，或经
  `JIT_SUBMIT`/`JIT_COMPILE`/`VM::jitCompile` 即时编译为原生函数指针（见 [14-JIT.md](14-JIT.md)）。
- **本层独立可用**：即使不用 j8c，也可以用 `jasm` 手写汇编（支持全部 68 条 opcode、函数与标签跳转、
  多格式数值、7 条伪指令），生成 VM 可执行的 v3 模块。
