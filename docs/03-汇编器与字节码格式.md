# 03. 汇编器与字节码格式（JadeightAbstractionCode）

本文档描述 Jadeight 生态的**汇编层**（`JadeightAbstractionCode`）：它把人类可读的 **jasm 汇编文本**汇编为 Jadeight2 虚拟机直接执行的 **`.bc` 字节码文件**。核心是一个 header-only 的 C++ 库 `jadeight_asm.hpp`（含 `Assembler` 类与全部 174 条 opcode 定义），被两个使用者复用：独立的命令行工具 `jasm` / `jasm_dbg`，以及 j8c 编译器（`JadeightCompiler` 内嵌调用）。字节码格式与 Jadeight2 虚拟机 `FunctionSave::loadFromFile` 完全兼容，因此 `.bc` 既能被解释器执行，也能被 LLVM JIT 编译成原生函数。

---

## 1. 定位与作用

```
        jasm 汇编文本（.jasm / .asm）
                    │
        jadeight_asm.hpp :: Assembler
        （第一趟收集标签 → 第二趟解析指令 → 第三趟解析头部并发射字节）
                    │
              .bc 字节码文件
        （12 字节头部 [argSize][retSize][entry] + 指令流）
                    │
        Jadeight2 虚拟机执行（解释器 / LLVM JIT）
```

- **汇编器本体**：`jadeight_asm.hpp`，约 1100 行，header-only、无外部依赖（仅标准库），C++20。
- **两种使用方式**：
  1. **独立 CLI**：`main.cpp`（编译产物 `jasm`、带调试信息的 `jasm_dbg`）——手动汇编/反汇编 `.asm` ↔ `.bc`；
  2. **库方式内嵌**：`JadeightCompiler`（j8c）`#include "jadeight_asm.hpp"`，在代码生成阶段直接调用 `Assembler::assemble()`，把编译器生成的 jasm 文本当场汇编成字节码，无需外部进程。
- **与 VM 的关系**：本层的 opcode 编号、指令编码、指令长度与 `Jadeight2/main.cpp` 中的解释器/LLVM JIT **逐字节一致**（opcode 表就是照着 VM 抄的，见 hpp 第 38 行注释"与 Jadeight2 VM 完全一致"）。

## 2. 源码结构与构建

目录结构：

```
JadeightAbstractionCode/
├── jadeight_asm.hpp      # 核心：Assembler 类 + opcode 表 + 名称表 + 指令长度表
├── main.cpp              # jasm 命令行薄入口（解析参数、读写文件、调 Assembler）
├── CMakeLists.txt        # add_executable(JadeightAbstractionCode main.cpp)，C++20
├── jasm                  # 编译好的 CLI（ELF x86-64，动态链接，无调试信息）
```

`CMakeLists.txt`（全文）：

```cmake
cmake_minimum_required(VERSION 4.3)
project(JadeightAbstractionCode)
set(CMAKE_CXX_STANDARD 20)
add_executable(JadeightAbstractionCode main.cpp)
```

手工编译（main.cpp 顶部注释给出的命令）：

```bash
g++ -std=c++20 -O2 main.cpp -o jasm
```

`jasm` 与 `jasm_dbg` 都是 ELF 64 位可执行文件（x86-64、PIE、动态链接）；`jasm_dbg` 带 `debug_info`、未 strip，供调试用。两者的命令行用法完全相同（见第 6 节）。

## 3. 汇编 API（jadeight_asm.hpp）

全部符号位于 `namespace jadeight`。

### 3.1 全局常量与工具函数

| 符号 | 作用 |
|---|---|
| `enum : uint8_t { OP_ERR_END = 0, OP_REG_MOVI_U8, ... OP_MEMCPY }` | **174 条 opcode**（0..173）。与 Jadeight2 VM 的枚举完全一致。`OP_ERR_END=0` 是哨兵/非法指令（VM 在字节码末尾追加 3 个作为越界保护）。 |
| `std::map<std::string,uint8_t> opNameMap` | 基础指令名 → opcode（`END`、`JMP`、`NEW_ARRAY`、`FUNC_CALL` 等 26 条无类型后缀的指令）。 |
| `void buildOpNameMapFull(std::map<std::string,uint8_t>&)` | 生成**完整助记符表**：在基础表上按"前缀 + 类型后缀"展开全部类型化指令（`REG_MOVI_U8..U64`、`ADD_U8..F64`、`CMP_LT_..PTR`、`ATOMIC_*` 等），`Assembler` 构造时调用。 |
| `size_t instrLen(uint8_t op)` | 指令编码长度（字节），用于反汇编与偏移计算；无操作数指令默认返回 1。 |
| `rdBE / wrBE<T>`、`rdLE / wrLE<T>` | 大端/小端多字节读写模板。**注意：指令内部的操作数一律按大端序写入**（`wrBE`），与头部字节序（可配置）无关。 |
| `uint64_t parseNum(const std::string&, bool& ok)` | 数值解析：十进制 / `0x` 十六进制 / `0` 八进制（`std::stoull` base 0），单字符字面量 `'A'`，转义 `'\n' '\t' '\0' '\\' '\''`。 |
| `int parseReg(const std::string&, bool& ok)` | 寄存器解析：`R0`~`R15`（`R`/`r` 均可），其余非法。 |
| `struct Instruction` | 中间表示：`uint8_t opcode`、`std::vector<uint64_t> operands`、`std::vector<std::string> labelRefs`（`@标签` 引用）、`size_t offset`（汇编后绝对偏移）。 |

### 3.2 Assembler 类

```cpp
class Assembler {
public:
    bool verbose = false;              // -v：每行打印 [pass1] 到 stderr
    bool pureBinary = false;           // -f：输出纯字节码，不带 12 字节头部
    bool littleEndianHeader = false;   // -e：头部按小端序读写（默认大端）
    std::string inputPath, outputPath; // 仅供 CLI 记录用，库调用可不设

    Assembler();                       // 构造时构建完整助记符表

    bool assemble(const std::string& asmText,
                  std::vector<uint8_t>& outBytes,
                  uint32_t& argSize, uint32_t& retSize, uint32_t& entry);

    bool disassemble(const std::vector<uint8_t>& bytes,
                     std::ostream& os, bool hasHeader);
};
```

**`assemble()`** —— 三趟流水线：

1. `splitLines` 预处理：按行切分，`;` 后为注释剔除，**逗号统一替换为空格**（因此操作数可用 `,` 或空格分隔，与反汇编输出格式一致、便于回环），去首尾空白；
2. `firstPass`：收集标签（`name:`）与伪指令，查完整助记符表把每行翻译成 `Instruction`，并按 opcode 校验操作数个数/取值范围；
3. `resolveLabels`：按指令长度累加计算每条指令的绝对偏移，把 `@标签` 解析成目标偏移（仅 `JMP` / `IF_GOTO` 支持标签引用）；
4. `emit`：解析头部伪指令（`.ARGS .RETS .ENTRY .ENTRYOFF`），写 12 字节头部（除非 `pureBinary`），再逐条把操作数按大端序编码进字节流。

**`disassemble()`** —— 反向过程：若 `hasHeader` 且字节数 ≥ 12，先按 `littleEndianHeader` 选定的字节序读出三个头部字段并打印 `.ARGS/.RETS/.ENTRY`（头部注释 `; FunctionSave header:`），然后按 `instrLen` 逐条解码打印（操作数用 `, ` 分隔，与汇编输入格式一致，可直接回汇编）。

### 3.3 j8c 如何调用它

`JadeightCompiler/CMakeLists.txt` 把汇编层加入头文件搜索路径：

```cmake
target_include_directories(j8c PRIVATE src ${CMAKE_CURRENT_SOURCE_DIR}/../JadeightAbstractionCode)
```

`src/driver.cpp` `#include "jadeight_asm.hpp"`，主流程为：词法 → 语法 → 语义 → 优化 → 代码生成 → **复用 jadeight_asm 汇编器** → `.bc`（LE 头，VM 兼容）。实际汇编发生在 `src/codegen.cpp` 的 `CodeGen::generate` 末尾：

```cpp
// 生成 jasm 文本（asmText）后，内嵌汇编器当场汇编
Assembler asmblr;
asmblr.pureBinary = true;                      // 只出指令流，头部由 driver 自己写
uint32_t as_, rs, en;
if (!asmblr.assemble(asmText, outBytes, as_, rs, en)) { ... }
// 汇编结果尺寸与编译器按标签/长度预测的尺寸比对（偏移正确性的强保证）
```

随后 `driver.cpp` 自己写 12 字节**小端序**头部再拼上字节码：

```cpp
uint8_t hdr[12];
jadeight::wrLE<uint32_t>(hdr, argSize);
jadeight::wrLE<uint32_t>(hdr + 4, retSize);
jadeight::wrLE<uint32_t>(hdr + 8, entry);
out.write(reinterpret_cast<const char*>(hdr), 12);
out.write(reinterpret_cast<const char*>(bc.data()), bc.size());
```

即：**j8c 走的是 `pureBinary + littleEndianHeader` 语义**（虽然它绕过 `assemble()` 的头部逻辑、直接在 driver 里用 `wrLE` 写头），产出与 `FunctionSave::loadFromFile` 兼容的 LE 头 `.bc`。加 `-S` 选项时，j8c 还会把 `asmText` 另存为 `.jasm` 文件供人查看。`JadeightCompiler/tools/dump_offsets.cpp`、`tools/j8trace.cpp` 也 `#include "jadeight_asm.hpp"` 复用 opcode 表与长度表。

## 4. jasm 汇编文本格式

### 4.1 词法

- **注释**：`;` 到行尾（`splitLines` 先掐掉，故 `;` 只能当注释，不能出现在操作数里）。
- **操作数分隔**：空格或逗号均可（`REG_MOVI_U64 R1, 4209` 与 `REG_MOVI_U64 R1 4209` 等价）。
- **助记符大小写不敏感**：解析时统一 `toupper`，`add_u64` 与 `ADD_U64` 等价。
- **数值**：十进制、`0x` 十六进制、`0` 前缀八进制、字符字面量 `'A'` 与转义 `'\n' '\t' '\0' '\\' '\''`。
- **寄存器**：`R0`~`R15`（共 16 个 64 位寄存器；指令编码时只取低 4 位）。

### 4.2 标签与跳转

- 标签单独成行、以 `:` 结尾：`loop:`；不允许重名，也不允许空标签。
- `JMP @label`（或 `JMP 绝对偏移`）—— u32 绝对跳转；
- `IF_GOTO cond, @label`（或 `IF_GOTO cond, 偏移`）—— `cond` 为 0..255 的 u8；
- `SHORT_JMP 相对偏移` —— i8 相对跳转（按字节码偏移相对计算）；
- 未定义的 `@标签` 报错 `Undefined label`；只有 `JMP` / `IF_GOTO` 接受标签引用。

### 4.3 伪指令

| 伪指令 | 语法 | 作用 |
|---|---|---|
| `.STACK n` | 头部 | 栈大小声明（汇编器只识别并跳过，不写入头部） |
| `.ARGS n` | 头部 | 参数区总字节数 → 写入头部 `argSize` |
| `.RETS n` | 头部 | 返回值字节数 → 写入头部 `retSize` |
| `.ENTRY n` | 头部 | 入口偏移 → 写入头部 `entry` |
| `.ENTRYOFF 标签` | 头部 | 入口取标签所在指令的偏移 → 写入 `entry` |
| `.BYTE v1 v2 ...` | 数据 | 逐字节原样发射（值取低 8 位） |
| `.FILL count, value` | 数据 | 连续发射 `count` 个值为 `value`（低 8 位）的字节 |

> 注：`.ARGS/.RETS/.ENTRY/.ENTRYOFF` 只影响头部；`.BYTE/.FILL` 直接嵌入指令流，汇编器不为其计算跳转偏移（跳转到数据区是允许的，但需自行保证语义）。

### 4.4 指令形式（按操作数形态分类）

**① 无操作数（栈机语义，操作数全走数据栈）** —— 四则/比较/位运算/转换/输出/作用域等：

```asm
ADD_U64          ; 弹栈两个 u64 相加，结果压栈
CMP_LT_I32       ; 弹两个 i32 比较，压 U8 的 0/1
COUT_CHAR8       ; 弹栈一个值输出（CHAR8 按字符、CHAR16/32 按数值）
SCOPE_PUSH / SCOPE_POP / END / GET_ADDRS / JMP_IND / SQRT_F64 ...
```

**② 带操作数指令** —— 关键几条（编码见第 5 节）：

```asm
REG_MOVI_U64 R1, 4209          ; 立即数 → 寄存器（U8/U16/U32/U64 四种宽度）
REG_MOV R1, R2                 ; 寄存器间拷贝（64 位）
REG_PUSH_U64 R1 / REG_POP_U32 R3
REG_LOAD_U64 R2, 0, 128        ; reg, mode(0|1), off:u64 —— mode0 栈槽 / mode1 弹指针解引用
REG_STORE_U8  R2, 1, 0
STACK_INIT 1024, 256           ; 栈大小, 作用域大小（u32, u32）
LEA 1, 16                      ; mode, off —— 压入地址
MOVI_U32 42                    ; 压入 4 字节立即数（大端）
NEW_STACK 4096                 ; bytes:u64
NEW_HEAP 0, 1024               ; slotOff:u32, size:u64
DEL_HEAP 0                     ; slotOff:u32
NEW_ARRAY 64, 8                ; size:u64, slotOff:u32
FREE_ARRAY 8                   ; slotOff:u32
EXTERN_CALL 3, 16, 32          ; idx:u8, argBaseOff:u32, retOff:u32
FUNC_CALL 24, 0, 64            ; fnPtrOff:u32, argBaseOff:u32, retOff:u32（调栈槽里的 FunctionSave*）
JIT_SUBMIT 24, 72              ; fnPtrOff:u32, retOff:u32（LLVM JIT 编译 save 并写回函数指针）
MEMCPY 0, 128, 1, 0, 64        ; dstMode, dstOff, srcMode, srcOff, size
```

> 注意：算术/比较等"无操作数"指令并非没有语义——VM 解释器对它们做 `popT`/`pushT` 栈操作（见 Jadeight2/main.cpp `DEF_ARITH_INT` 宏），**给它们写操作数会报错**（`Instruction N does not take operands`）。

### 4.5 完整示例（可汇编、可反汇编回环）

```asm
; example.asm —— R1=4209, R2=5，求和入 R3
.ARGS 0
.RETS 0
.ENTRY 0

STACK_INIT 1024, 256        ; 建立栈：1024 字节栈 + 256 字节作用域
REG_MOVI_U64 R1, 4209
REG_MOVI_U64 R2, 5
REG_PUSH_U64 R1            ; 操作数压栈
REG_PUSH_U64 R2
ADD_U64                    ; 弹 5 和 4209，压 4214
REG_POP_U64 R3
END
```

```bash
./jasm example.asm -o example.bc -v        # 汇编
./jasm example.bc -d                       # 反汇编回文本
```

## 5. 字节码 .bc 文件格式

### 5.1 文件布局

```
┌─────────────────────────────────────────────┐
│ 头部 12 字节（默认大端，可 -e 切换小端）       │
│   [0..4)   argSize : u32   参数区总字节数     │
│   [4..8)   retSize : u32   返回值字节数       │
│   [8..12)  entry   : u32   入口偏移（指令计数）│
├─────────────────────────────────────────────┤
│ 指令流（与头部字节序无关，操作数恒为大端）      │
│   opcode : u8  +  操作数（按各指令格式）       │
└─────────────────────────────────────────────┘
```

**字节序规则（关键）**：
- **头部**：`Assembler` 默认**大端**（`wrBE`），与自身反汇编回环一致；设 `littleEndianHeader=true`（CLI 的 `-e`/`--le`）后改为**小端**，与 Jadeight2 虚拟机 `FunctionSave::loadFromFile` 的文件格式一致；j8c 直接用小端写头。
- **指令内部的多字节操作数恒为大端序**（`emit()` 一律 `wrBE`），与头部字节序无关。VM 端也用模板 `rdBE` 读操作数（Jadeight2/main.cpp 第 5 行注释：字节码取数用模板 rdBE/wrBE 大端序手工拼字节）。

实测两种头部（`.ARGS 12 / .RETS 4 / .ENTRY 16`）：

```
BE:  00 00 00 0c | 00 00 00 04 | 00 00 00 10 | 16 ...
LE:  0c 00 00 00 | 04 00 00 00 | 10 00 00 00 | 16 ...
```

（`16` 是 `END` 的 opcode。）

### 5.2 指令编码与长度

每条指令 = 1 字节 opcode + 定长操作数，操作数多字节字段大端。汇编器依据 `instrLen(op)` 表计算偏移；常见指令：

| 指令 | 长度 | 编码（opcode 之后） |
|---|---|---|
| `REG_MOVI_U8/U16/U32/U64` | 3 / 4 / 6 / 10 | `reg:u4` + `imm:u8/u16/u32/u64` |
| `REG_MOV` | 3 | `dst:u4 src:u4` |
| `REG_PUSH/POP_*` | 2 | `reg:u4` |
| `REG_LOAD/STORE_*` | 11 | `reg:u4 mode:u8 off:u64` |
| `STACK_INIT` | 9 | `stackSize:u32 scopeSize:u32` |
| `JMP` | 5 | `addr:u32`；`SHORT_JMP` 2 字节 `rel:i8` |
| `IF_GOTO` | 6 | `cond:u8 addr:u32` |
| `LEA` | 10 | `mode:u8 off:u64`；`MOVI_U32` 5 字节 `imm:u32` |
| `NEW_STACK` | 9 | `bytes:u64`；`NEW_HEAP` 13 = `slotOff:u32 size:u64`；`DEL_HEAP` 5 |
| `NEW_ARRAY` | 13 | `size:u64 slotOff:u32`；`FREE_ARRAY` 5 |
| `ATOMIC_*` | 11 | `reg:u4 mode:u8 off:u64` |
| `EXTERN_CALL` | 10 | `idx:u8 argOff:u32 retOff:u32` |
| `FUNC_CALL` | 13 | `fnOff:u32 argOff:u32 retOff:u32` |
| `JIT_SUBMIT` | 9 | `fnOff:u32 retOff:u32` |
| `MEMCPY` | 27 | `dstMode:u8 dstOff:u64 srcMode:u8 srcOff:u64 size:u64` |
| 其余（算术/比较/位运算/转换/COUT/作用域/`GET_ADDRS`/`JMP_IND`/`END`/`OP_ERR_END`） | 1 | 无操作数 |

> `mode`（0/1）语义：`mode0` 直接读写栈内 `[基址+off]`（栈槽寻址）；`mode1` 先从栈顶弹一个指针再按指针解引用读写（与 `LEA` 一致）。`END` 正常退出；`OP_ERR_END` 是 VM 加载时在字节码**末尾追加 3 个**的越界哨兵（文件本身不含，见 Jadeight2/main.cpp 的 `save` 构造），解释器读到即安全退出。

### 5.3 兼容性：FunctionSave::loadFromFile

`Jadeight2/main.cpp` 的 `FunctionSave::loadFromFile(path)`：

```cpp
uint32_t hdr[3] = {0,0,0};
fread(hdr, 4, 3, f);                 // 按小端读入 argSize, retSize, entry（宿主机 x86 小端）
fseek(f, 12, SEEK_SET);              // 跳过 12 字节头部
fread(buf, 1, sz, f);                // 其余为函数字节码
return FunctionSave(buf.data(), buf.size(), hdr[2], hdr[0], hdr[1]);
```

- 文件 = **12 字节小端头部** + 函数字节码；头部字段顺序 `argSize, retSize, entry`，与汇编器 `assemble()` 的三个输出参数一一对应。
- `FunctionSave` 内部复用 VM 的 `save`（字节码，构造时追加 3 个 `OP_ERR_END` 哨兵并 `mprotect` 冻结为只读）+ 独立的 `DataSave`（自己的栈/寄存器）+ `executoring`（解释器），`entry` 作为指令计数起点（`count`）。
- **调用约定**：被 `FUNC_CALL` 调用时 `R15`=参数基址指针、`R14`=返回值地址指针；函数字节码以 `STACK_INIT` 开头、`END` 收尾（`silent=1` 抑制退出打印），每次调用栈全新分配/释放。
- 因此：**j8c 输出的 `.bc` 和 `jasm -e` 输出的 `.bc` 可直接被 VM `loadFromFile` 加载**；`jasm` 默认的大端头文件则需 `-e` 转换后才与 VM 文件格式一致（反汇编回环无此限制，`Assembler::disassemble` 两种字节序都支持）。

实测汇编产物（第 4.5 节示例，BE 头）hexdump：

```
00000000: 0000 0000 0000 0000 0000 0000 1700 0004  ................   <- 12B 头 + STACK_INIT 0x17
00000010: 0000 0001 0004 0100 0000 0000 0010 7104  ................   <- REG_MOVI_U64 R1,4209
00000020: 0200 0000 0000 0000 0509 0109 0226 0d03  .............&..
00000030: 16                                       .                  <- END (0x16)
```

（`0x17`=STACK_INIT、`0x01`=REG_MOVI_U64、`0x09`=REG_PUSH_U64、`0x26`=ADD_U64、`0x0d`=REG_POP_U64、`0x16`=END。）

## 6. jasm / jasm_dbg 可执行文件

两者是同一个 CLI（`main.cpp`）的两种构建；`jasm_dbg` 带调试信息供 gdb 调试。用法（实测运行输出）：

```
Usage: ./jasm input.asm [-o output.bc] [-d] [-v] [-f] [-e]
```

| 选项 | 含义 |
|---|---|
| `input.asm` | 汇编输入（必须）；默认输出同名前缀 `.bc` |
| `-o output.bc` | 指定输出文件（汇编模式写 `.bc`；反汇编模式可写文本清单） |
| `-d` | **反汇编模式**：输入是 `.bc`，输出可读指令清单（到 stdout 或 `-o` 文件） |
| `-v` | 详细输出：逐行打印 `[pass1] ...`、结果统计与头部信息 |
| `-f` | 输出**纯字节码**（不带 12 字节头部；反汇编模式则按无头字节流处理） |
| `-e` / `--le` | 头部按**小端序**读写（VM `loadFromFile` 兼容；默认大端） |

示例：

```bash
./jasm hello.asm                    # hello.asm -> hello.bc（BE 头）
./jasm hello.asm -o out.bc -e -v    # LE 头 + 详细输出
./jasm out.bc -d                    # 反汇编
./jasm out.bc -d -o out.jasm        # 反汇编结果写文件（可再汇编回去）
./jasm raw.bin -d -f                # 无头字节流反汇编
```

注意：反汇编**无法区分数据与代码**——若 `.bc` 里嵌了 `.BYTE/.FILL` 数据区，反汇编器会把数据当 opcode 解码成乱码（这是格式本身的固有限制，不是 bug）。

## 7. 与生态的关系

```
   j8c（JadeightCompiler）                 jasm（本层 CLI）
   .j8 源码 ──词法/语法/语义/优化──> jasm 文本   手写 .jasm 文本
        │  CodeGen::generate                          │
        │  （内嵌 Assembler，pureBinary）              │  ./jasm [ -e ]
        ▼                                              ▼
   .bc（LE 头 + 字节码）◄──────────── .bc（BE 头，需 -e 转 LE）
        │
        ▼
   Jadeight2 虚拟机（02-Jadeight2虚拟机.md）
   FunctionSave::loadFromFile 加载 → 解释器 executoring 逐条执行
   └─ 可选：JIT_SUBMIT / JadeightJIT::submit → LLVM O2 原生码
```

- **承接**：j8c（见 04-j8c编译器.md）的词法/语法/语义/优化全部完成后，`CodeGen` 把 IR 发射成 jasm 文本（`.ARGS/.RETS/.ENTRY` 头 + 逐函数指令 + 数据段），再内嵌调用本层 `Assembler` 汇编成字节码，最后 driver 补写 LE 头。`-S` 选项保留的 `.jasm` 就是这一中间文本，可交给 `jasm` 手工再汇编。
- **产出**：`.bc` 被 Jadeight2 虚拟机消费——`FunctionSave::loadFromFile` 直接加载（解释执行），或经 `JIT_SUBMIT`/`JadeightJIT::submit` 即时编译为原生函数指针。`JadeightPoject/byteCode/` 目录下的 `t1_basic.bc`、`t3_functions.bc` 即为实际产物示例。
- **本层独立可用**：即使不用 j8c，也可以用 `jasm` 手写汇编（支持全部 174 条 opcode、标签、多格式数值、7 条伪指令），生成 VM 可执行的 `.bc`。
