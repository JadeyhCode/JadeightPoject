# Jadeight 生态总体架构

Jadeight 是一个自底向上的字节码虚拟机生态。当前指令集是 **ISA v3**（合并式指令集：
类型宽度/符号/是否浮点降级为指令参数 `TypeDesc`，opcode 合并为 **68 条**）。

> **ISA 的唯一事实源是 [`Jadeight2ReWrite/isa.hpp`](../../Jadeight2ReWrite/isa.hpp)**：
> opcode 枚举、`TypeDesc`、指令长度表 `instrLen`、模块文件格式 `ModuleImage`
> （`serialize`/`deserialize`）全在那里。编译器 / 汇编器 / 运行器 / 启动器 / JIT
> 一律以它为准；本文与源码不一致时以源码为准。
>
> 注意：文件头/CMakeLists 里曾出现过的 opcode 计数（66、67）都是迁移途中的旧数字，
> 已统一订正为 **68 条**（按 `enum Op` 实际统计，含 10 条 `THREAD_*`/`PROC_*`）。
> 逐条说明见 [06-指令集参考.md](06-指令集参考.md)。
> 另：`instrLen` 与 `opLenFixed` 两张长度表必须等于 `Asm` 编码器的真实字节数——
> `OP_PROC_SPAWN` 曾漏成 6（实为 `u16 + u32` = 7），已修复并由 VM 自测常驻看护。

## 数据流

```
.j8 源码
  │  j8c（JadeightCompiler）—— 词法/语法/语义/优化/代码生成
  │      代码生成产出 jasm 汇编文本（-S 时留在 <out>.jasm），并复用汇编层一次成型
  ▼
.bc（ISA v3 模块：magic "J3BC" + 函数目录 + 码流）
  │  j8run 程序.bc [--jit]                ← 最直接的运行入口
  │  或 启动器 ./run.sh / ./build/JadeightPoject（先找 VM，再交给它跑）
  ▼
VM 本体 Jadeight2ReWrite：解释器 或 copy-and-patch 模板 JIT
  ▼
程序输出

.jasm 汇编文本
  │  jasm（JadeightAbstractionCode）
  ▼
.bc（同一个 v3 模块格式）
  │  jasm -d —— 反汇编（读 .bc，输出可再汇编的 .jasm 文本）
  ▼
.jasm 汇编文本
```

## 组件关系

- **`isa.hpp` 是唯一的指令集事实源**：opcode 编号、助记名（`opName`）、每条指令的长度
  （`instrLen`）、类型描述符（`tdWidth`/`tdSigned`/`tdFloat`/`tdBytes`）与 `.bc` 模块格式
  都定义在这里，没有第二份。
- **j8c 编译** `.j8` 源文件：词法 → 语法 → 语义（协议/泛型/ECS）→ 优化 → 代码生成（jasm 文本），
  再复用 `jadeight_asm.hpp` 直接产出 **v3 模块**；`-S` 会把中间那份 `.jasm` 文本留在 `.bc` 旁边。
- **`.bc` 就是 ISA v3 模块格式，全小端**（`ModuleImage`，编译器/汇编器/运行器/启动器共用）：
  magic `"J3BC"`(4B) + u32 version(=3) + u32 funcCount + u32 codeSize + u32 entryFunc +
  funcCount × 20B `{offset,size,argSize,retSize,entry}` + 码流。
  函数在码流里首尾相接，`JMP`/`BRANCH` 的标签是**函数相对**偏移，所以单个函数位置无关、
  整个模块也可以重定位。入口函数下标读自模块头（j8c 的 `main` 不一定是 0 号函数）。
- **jasm**（`JadeightAbstractionCode/main.cpp`，核心在 header-only 的 `jadeight_asm.hpp`）：
  汇编 `.jasm` → v3 模块（默认 `input.jasm` → `input.bc`）；`jasm -d` 反汇编 `.bc` 回
  可再汇编的 `.jasm` 文本（函数边界输出为 `.FUNC`，标签为函数相对 `L<n>`）。
- **VM 本体是 `Jadeight2ReWrite`**：`Jadeight2.cpp` 里是解释器、`save`（模块 = 连续码流 +
  函数目录；装载后拷进页对齐映射、追加哨兵、`mprotect` 冻结为只读）、`Thread`、`Process`、`VM`；
  `jit.hpp` 里是 copy-and-patch 模板 JIT（`Jit` / `VM::jitCompile` / `VM::jitCompileBlob`）。
  ISA v3 提供 3 条 JIT 指令：`JIT_SUBMIT` / `JIT_COMPILE` / `CALL_NATIVE`——用法与内部结构
  见 [14-JIT.md](14-JIT.md)，本文不重复。
- **j8run**（`JadeightCompiler/runtime/j8run.cpp`）是宿主运行器：`#define main jadeight2_vm_main`
  之后 `#include` 整个 `../Jadeight2ReWrite/Jadeight2.cpp`，因此解释语义与 VM 完全一致；
  它接受 `.bc` 路径参数，是**当前跑 .bc 模块的推荐入口**。
- **JadeightPoject 启动器** 把整条链串起来：自动寻找能跑 `.bc` 的 VM（本机命中 `j8run`），
  依次运行 `./byteCode/*.bc`，并把 `--externs`/`--lib` 透传给 VM。
