## 1. 总览与编码约定

### 1.1 指令总数

- **真实指令 177 条**：opcode 编号 **1..177**（十六进制 0x01..0xB1）。
- **opcode 0 = `OP_ERR_END`**（哨兵指令，不计入 177 条）：`save` 构造时在字节码末尾追加 3 个 `OP_ERR_END`，解释器指令计数越界读到哨兵即跳 `ITP_ERR_END` 安全退出（`end=2` 越界退出，释放 Stack 与作用域栈）。枚举里共有 178 个值（0..177），其中 0 是哨兵。

### 1.2 编码约定

- 每条指令 = **1 字节操作码 + 0..多个操作数**。
- 多字节操作数一律**大端序**（big-endian，模板 `rdBE`/`wrBE` 读写，反汇编回环一致）。
- 寄存器下标 1 字节、**低 4 位有效**（`R0..R15`，jasm 里大小写不敏感：`R3` 或 `r3`），解释器**无越界检查**。
- 立即数支持十进制/`0x` 十六进制/字符字面量（`'a'`、`'\n'` 等，见 `parseNum`）。
- 指令操作数在 jasm 里**逗号或空格分隔均可**（汇编器把逗号替换为空格）。
- `.bc` 文件格式：可选 12 字节头部 `[argSize:u32][retSize:u32][entry:u32]`（默认大端序；`-e` 选项改小端序与 VM `FunctionSave::loadFromFile` 兼容；`-f` 纯二进制无头部）+ 指令流。
- 两条伪指令（**不是 opcode**）：`.BYTE v...`（0xFF，直接发射原始字节）、`.FILL count, value`（0xFE，填充 count 个 value 字节）。
- 栈语义：`pushT` 在 `Stack[sp]` 写 `sizeof(T)` 字节后 `sp += sizeof(T)`；`popT` 先 `sp -= sizeof(T)` 再读——**栈向高地址增长**。所有"弹 b、a，压 a OP b"的指令，b 是栈顶、a 是栈顶之下一个。
- 作用域基址：`SCOPE_BASE = zuoYongYvStackPtr[zuoYongYv - 1]`，所有"栈槽偏移 off"都相对 `SCOPE_BASE` 计算，即 `Stack[base + off]`。
- 两种寻址 mode（`REG_LOAD/STORE`、`LEA`、`ATOMIC_*`、`MEMCPY` 共用）：
  - **mode0**：直接操作 `Stack[base + off]` 本身；
  - **mode1**：先从 `Stack[base + off]` 读 8 字节当作指针，再解引用该指针操作。

### 2.9 比较 CMP_*（92..124）

## 3. 指令编码格式

### 3.1 总规则

```
指令 = 操作码（1 字节）+ 操作数（按固定顺序，多字节一律大端序）
```

各操作数类型与字节数（由 `instrLen` 与 `emit` 共同确定）：

| 操作数类型 | 字节数 | 说明 |
|---|---|---|
| reg | 1 | 寄存器下标，低 4 位有效（R0..R15） |
| immW / uW / iW | W/8 | 立即数或宽度 W 的值 |
| u32 | 4 | 32 位立即数/偏移/地址，大端序 |
| u64 | 8 | 64 位立即数/偏移/尺寸，大端序 |
| mode | 1 | 0 或 1（寻址模式） |
| idx | 1 | EXTERN_CALL 的表下标（0..255） |

无操作数指令（算术/位运算/比较/SQRT/LOG/CVT/COUT/END/SCOPE_*/ADD_PTR/SUB_PTR/GET_ADDRS/JMP_IND 等）= 只有 1 字节操作码。

### 3.2 完整例子：`REG_MOVI_U32 R3, 0x12345678`（opcode 3，长度 6）

`Assembler::emit` 逐字节过程（`OP_REG_MOVI_U32` 分支）：

```
操作码       0x03                          （1 字节）
reg         0x03                          （operands[0] & 0x0F）
imm         wrBE<uint32_t>(p, 0x12345678) → 12 34 56 78   （4 字节大端序）
─────────────────────────────────────────
编码结果：03 03 12 34 56 78   （共 6 字节，与 instrLen(3)=6 一致）
```

解释器侧 `ITP_REG_MOVI_U32` 反向读取：`reg = byteCode[count+1]`，`rdBE<uint32_t>(byteCode+count+2)` 拼出 `0x12345678` → `Regs[3] = 0x12345678`。

### 3.3 完整例子：带标签的 `JMP`（opcode 24，长度 5）

```
.ARGS 0
.RETS 0
.ENTRYOFF start
start:            ; 标签 → 指令偏移 0
  JMP @start      ; 解析为绝对偏移 0
```

汇编流程（三趟）：第一趟收集标签与指令偏移（`JMP` 长度 5，start 偏移 0）；`resolveLabels` 把 `@start` 解析为 `targetOffset = 0` 写入操作数；`emit` 发射：

```
操作码       0x18                          （24）
addr        wrBE<uint32_t>(p, 0) → 00 00 00 00
─────────────────────────────────────────
编码结果：18 00 00 00 00   （共 5 字节）
```

加头部（默认大端序）后整文件 12 + 5 = 17 字节：

```
头部: 00 00 00 00 | 00 00 00 00 | 00 00 00 00   （argSize=0, retSize=0, entry=0）
指令: 18 00 00 00 00
```

### 3.4 完整例子：栈程序（含 MOVI_U32 / COUT_CHAR32 / END）

```
.ARGS 0
.RETS 0
.ENTRYOFF start
start:
  MOVI_U32 42     ; opcode 34 (0x22) + imm32 BE
  COUT_CHAR32     ; opcode 91 (0x5B)
  END             ; opcode 22 (0x16)
```

逐字节：

| 行 | 指令 | 字节 | 说明 |
|---|---|---|---|
| 1 | MOVI_U32 42 | `22 00 00 00 2A` | 操作码 0x22 + `wrBE<uint32_t>(42)` = `00 00 00 2A` |
| 2 | COUT_CHAR32 | `5B` | 无操作数 |
| 3 | END | `16` | 无操作数 |

指令流共 7 字节；运行时 42 被压栈（4 字节）、弹出打印为 "42"、正常退出。

### 3.5 复杂操作数布局示例（`MEMCPY`，opcode 174，长度 27）

`MEMCPY(dstMode:u8, dstOff:u64, srcMode:u8, srcOff:u64, size:u64)` 的逐字节布局：

```
偏移 0     操作码 0xAE
偏移 1     dstMode（1 字节）
偏移 2..9  dstOff（8 字节大端序）
偏移 10    srcMode（1 字节）
偏移 11..18 srcOff（8 字节大端序）
偏移 19..26 size（8 字节大端序）
```

例如 `MEMCPY 0, 8, 1, 16, 4` 编码为：
`AE 00 00 00 00 00 00 00 08 01 00 00 00 00 00 00 00 10 00 00 00 00 00 00 00 04`（27 字节）。

其他带 u32 布局的指令同理（如 `FUNC_CALL` = `AC` + 3×u32、`EXTERN_CALL` = `AB` + idx + 2×u32、`NEW_ARRAY` = `9D` + u64 + u32、`NEW_HEAP` = `1E` + u32 + u64）。

### 3.6 反汇编一致性

`Assembler::disassemble` 按 `instrLen` 定长推进并逐操作数还原（寄存器 `R{n}&0x0F`、`mode{n}`、`@addr`、`slotOff=`/`size=` 等），与 `emit` 编码严格互逆——jasm 与 `.bc` 可无损失回环（round-trip）。

## 4. 附注与已知约定

- **哨兵机制**：`save` 构造时在字节码末尾追加 3 个 `OP_ERR_END`（0x00）哨兵并 `mprotect` 冻结为只读；解释器**不做任何越界检查**，越界读到哨兵即安全退出（`end=2`）。
- **类型哲学**：类型只在编译期确定——每个 `(运算 × 类型)` 组合是独立 opcode，运行期解释器没有"类型"概念，只按每条指令自己的 `sizeof(T)` 读写字节。
- **CHAR8/16/32 与 U8/U16/U32 位模式一致**，v2.03 起仅 COUT 保留 char 语义（CHAR8 按字符输出，CHAR16/32 按数值输出）。
- **条件跳转注意**：`IF_GOTO` 在 `cond == 0` 时跳转（与常见"条件为真则跳"相反）。
- **SHORT_JMP 公式较特殊**：按源码逐字描述（`b>0x7F` 时 `count -= (b-129)`，否则 `count += (b+2)`），请勿按常规 i8 相对跳转推演。
- **REG_PUSH/POP 与 LOAD/STORE 的宽度变体**均为无符号零扩展语义。
- 本文档不包含"待确认"项——所有 opcode 编号、长度、jasm 语法与语义均已从源码逐一核对。
