## 1. 一句话说清 v3 改了什么

v2 把**类型焊进 opcode**：`OP_ADD_U8`、`OP_ADD_U16`、`OP_ADD_I8`… 一个运算 × 4 种宽度 ×
有/无符号 × 浮点，很快吃掉几百个 opcode。

v3 把**宽度 / 符号 / 是否浮点 / 是否指针**压成一个**参数字节（TypeDesc）**跟在 opcode 后面：

```
v2:  ADD_U8 / ADD_U16 / ADD_U32 ...      ← 每种宽度一条
v3:  ADD u8 / ADD u16 / ADD u32 ...      ← 一条指令 + 一个参数
```

**关键：合并的是「编码空间」，不是「执行效率」。** 解释器和 JIT 拿到 TD 后会把它映射回
**特化的 C++ 类型**（`withIntType` / `withFpType`），热路径仍是 `sizeof(T)` 在编译期定死的
代码，运行期没有类型分支。合并省下的 opcode 空间用来做原生支持：多函数、线程、进程，
以及 3 条 JIT 指令。

## 2. 类型描述符 TD（v3 的核心）

TD 是**一个字节**，跟在需要类型的 opcode 之后：

| 位 | 含义 |
|---|---|
| bit0-1 | **宽度**：0=1B 1=2B 2=4B 3=8B |
| bit2 | **符号**：0=无符号 1=有符号（只在实现真的不同时才被读取） |
| bit3 | **浮点**：0=整数 1=浮点（此时宽度 2→f32、3→f64） |
| bit4 | **指针**：1=指针（恒 8 字节，做指针算术） |
| bit5-7 | 预留（零/符号扩展策略、饱和等） |

| TD | 值 | 含义 |
|---|---|---|
| `TD_U8` `TD_U16` `TD_U32` `TD_U64` | 0 1 2 3 | 无符号整数 |
| `TD_I8` `TD_I16` `TD_I32` `TD_I64` | 4 5 6 7 | 有符号整数 |
| `TD_F32` `TD_F64` | 10 11 | 浮点 |
| `TD_PTR` | 19 | 指针 |

符号只是 bit2 —— 所以「同宽度、只差一个 bit」的有/无符号天然是同一个 opcode，
这就是合并的物理基础。

---

## 3. 编码约定

- **一条指令 = 1 字节 opcode + 定长操作数**；类型化指令的第二个字节是 TD。
- **操作数一律小端**（v2 是「12 字节文件头 LE + 指令流操作数 BE」的混搭，v3 统一了）。
- **跳转只有标签跳转**：`JMP` / `BRANCH` 的操作数是**函数相对 label 偏移**。
  - 没有 PC 相对跳转。JIT 只要建一张「label → 原生地址」表就能落点，不必按
    「原生码长度 vs 字节码长度」的差做换算。
  - 因此**函数在模块内位置无关**。
- 间接跳转/调用用模块内**绝对地址**：`JMP_IND`（弹）、`CALL_IND reg`（字节码地址）、
  `CALL_NATIVE reg`（原生地址）。

## 4. 指令表

### 4.1 控制流（0x00–0x0F）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0x00 | `TRAP` | — | 哨兵/非法指令：安全退出（函数尾部追加 3 个） |
| 0x01 | `NOP` | — | 空操作 |
| 0x02 | `HALT` | — | 正常结束当前线程 |
| 0x03 | `JMP` | `label:u32` | 无条件跳到函数相对 label |
| 0x04 | `BRANCH` | `label:u32` | 弹 u8 条件；非 0 跳 label，否则落空继续 |
| 0x05 | `CALL` | `funcIdx:u16, argBaseOff:u32, retOff:u32` | 调模块内第 funcIdx 个函数 |
| 0x06 | `CALL_IND` | `reg:u8, argBaseOff:u32, retOff:u32` | 目标从寄存器取（**字节码**绝对地址） |
| 0x07 | `RET` | — | 弹帧返回；根帧 RET = 线程结束 |
| 0x08 | `JMP_IND` | — | 弹 u64 绝对地址跳转（配 `FUNC_ADDR`） |

**调用约定**（`CALL` / `CALL_IND` / `CALL_NATIVE` 一致）：

- 调用时预置 **R15 = 参数基址指针**、**R14 = 返回值地址指针**（相对当前作用域基址）。
- 被调函数帧基址 = **调用者 CALL 时的 stackPtr**；`STACK_INIT` 据此建自己的帧。
- `RET` 用帧栈还原 sp / 作用域深度 / R14 / R15 / fnBase。
- **寄存器是 caller-saved**：CALL 破坏 R0–R13，跨调用要保留的值必须落栈槽。

### 4.2 栈 / 作用域（0x10–0x1F）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0x10 | `STACK_INIT` | `size:u32, scopeSize:u32` | 确保容量；帧基址=当前帧的 stackPtr；sp 不前移 |
| 0x11 | `SCOPE_PUSH` | — | `scope[depth]=sp; depth++` |
| 0x12 | `SCOPE_POP` | — | **先取 `scope[depth-1]` 再减 depth**（反了会退到外层作用域） |
| 0x13 | `STACK_MOVE` | `n:u32` | `sp -= n` |
| 0x14 | `STACK_ALLOC` | `n:u64` | `sp += n`（按需扩容并修正 R14/R15） |

### 4.3 内存（0x20–0x2F）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0x20 | `LOAD` | `td, reg:u8, mode:u8, off:u32` | 取数进寄存器 |
| 0x21 | `STORE` | `td, reg:u8, mode:u8, off:u32` | 寄存器写回内存 |
| 0x22 | `LEA` | `mode:u8, off:u32` | 压地址 |
| 0x23 | `NEW_HEAP` | `off:u32, size:u64` | 堆分配，指针写入栈槽 |
| 0x24 | `DEL_HEAP` | `off:u32` | 释放栈槽里的指针 |
| 0x25 | `NEW_ARRAY` | `size:u64, off:u32` | 同上（`uint8_t[]`，无类型） |
| 0x26 | `FREE_ARRAY` | `off:u32` | 释放 |
| 0x27 | `MEMCPY` | `dstMode:u8, dstOff:u64, srcMode:u8, srcOff:u64, size:u64` | memcpy |
| 0x28 | `GET_ADDRS` | — | 压 4 个 u64：code 基址、size 字段地址、`Thread*`、`Manager*` |

**mode 的含义**（`LOAD`/`STORE`/`LEA`/`MEMCPY` 通用）：

- `mode=0`：操作数就是**栈槽本身**（地址 = `stack + 作用域基址 + off`）。
- `mode=1`：**先把栈槽里的值当指针**，再对它操作。

⚠️ 想取「指针本身」要用 `mode=0`，用错会多解一次引用。

### 4.4 移动 / 立即数（0x30–0x3F）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0x30 | `MOVI` | `td, reg:u8, imm(width)` | 立即数进寄存器（宽度由 TD 定；有符号则符号扩展） |
| 0x31 | `MOV` | `dst:u8, src:u8` | 寄存器间传送 |
| 0x32 | `PUSH_REG` | `td, reg:u8` | 寄存器压栈 |
| 0x33 | `POP_REG` | `td, reg:u8` | 弹栈进寄存器（有符号则符号扩展） |
| 0x34 | `PUSH_IMM` | `td, imm(width)` | 立即数压栈（v2 的 `MOVI_U32` 合并而来） |

### 4.5 算术（0x40–0x4F，各带 1 个 TD）

| 编码 | 助记名 | 语义 | 符号位是否生效 |
|---|---|---|---|
| 0x40 | `ADD` | 弹 b、a，压 `a+b` | 否（补码下位模式相同） |
| 0x41 | `SUB` | 压 `a-b` | 否 |
| 0x42 | `MUL` | 压 `a*b` | 否 |
| 0x43 | `DIV` | 压 `a/b` | **是**（`div` vs `idiv`）；除 0 得 0 |
| 0x44 | `REM` | 压 `a%b` | **是** |
| 0x45 | `NEG` | 压 `-a` | 否（浮点也支持） |

`TD_PTR` 的 `ADD`/`SUB` 就是 v2 的 `ADD_PTR`/`SUB_PTR`。

### 4.6 位运算（0x50–0x5F，各带 1 个 TD）

| 编码 | 助记名 | 语义 | 符号位是否生效 |
|---|---|---|---|
| 0x50 | `SHL` | `a << (b & (位宽-1))` | 否 |
| 0x51 | `SHR` | 右移 | **是**（逻辑 `shr` vs 算术 `sar`） |
| 0x52 | `AND` | 按位与 | 否 |
| 0x53 | `OR` | 按位或 | 否 |
| 0x54 | `XOR` | 按位异或 | 否 |
| 0x55 | `NOT` | 按位取反 | 否 |

### 4.7 比较 / 数学（0x60–0x6F）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0x60 | `CMP` | `sub:u8, td` | 弹 b、a，按 sub 比较，压 u8 结果 |
| 0x61 | `SQRT` | `td` | 压 `sqrt(a)`（f64） |
| 0x62 | `LOG` | `td` | 压 `log(a)`（f64） |

`CMP` 的 sub：`0=LT 1=LE 2=EQ 3=NE 4=GT 5=GE`。**一次编码覆盖 6 种比较 × 全部类型**
（v2 里这是 33 条 opcode，而且没有 LE/NE/GE，要靠组合拼）。

符号位在 `LT/LE/GT/GE` 上生效（`setl` vs `setb`）；`EQ/NE` 不需要。

### 4.8 转换（0x70）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0x70 | `CVT` | `srcTd, dstTd` | 弹出源类型，压入目标类型 |

整数↔浮点、有符号↔无符号都在这一条里（v2 是 8 条 `CVT_*`）。

### 4.9 系统 / IO / FFI（0x80–0x8F）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0x80 | `COUT` | `td` | 弹出并打印（`u8`/`i8` 按字符，其余按数值/浮点） |
| 0x81 | `GET_SYSTEM` | — | 压系统信息 u64（低 16 位平台、次 16 位架构） |
| 0x82 | `EXTERN_CALL` | `idx:u8, argBase:u32, retOff:u32` | 经 libffi 调外部 C 函数（原样透传） |
| 0x83 | `DL_REG` | `fnOff:u32, sigOff:u32, outOff:u32` | 运行期注册外部函数，索引写槽 |
| 0x84 | `DL_CALL` | `idxOff:u32, argBase:u32, retOff:u32` | 调 `externFn[idx]` |

### 4.10 JIT（0x85–0x87）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0x85 | `JIT_SUBMIT` | `funcIdx:u16, outOff:u32` | 编译模块内第 funcIdx 个函数，入口指针写槽 |
| 0x86 | `JIT_COMPILE` | `ptrOff:u32, lenOff:u32, outOff:u32` | 编译**任意一串字节码**（指针/长度从槽读），入口指针写槽 |
| 0x87 | `CALL_NATIVE` | `reg:u8, argBaseOff:u32, retOff:u32` | 调寄存器里的**原生**入口 |

- 三条合起来是闭环：**编译函数 / 编译任意码流 / 调用原生入口**。
- `JIT_COMPILE` 的码流会被 JIT 拷贝留存（产物里 `EXTERN_CALL`/`DL_*` 把那段地址当立即数用）；
  相同内容二次编译命中缓存，返回同一个指针。
- `CALL_IND` 的目标是**字节码**地址，`CALL_NATIVE` 的目标是**原生**地址 —— 两者互补。
- 详见 [14-JIT.md](./14-JIT.md)。

### 4.11 原子变量（0x90–0x9F，各带 TD）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0x90 | `ATOMIC_LOAD` | `td, reg:u8, mode:u8, off:u32` | 原子读进寄存器 |
| 0x91 | `ATOMIC_STORE` | 同上 | 原子写 |
| 0x92 | `ATOMIC_XCHG` | 同上 | 交换，寄存器拿到旧值 |
| 0x93 | `ATOMIC_CAS` | 同上 | 弹 expected；相等则写；寄存器=实际旧值，压 u8 成功标志 |
| 0x94 | `ATOMIC_ADD` | 同上 | `fetch_add`，**寄存器拿到旧值**（加数每轮要重置） |

TD 只允许 4 / 8 字节整数。

### 4.12 函数（0xA0）

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0xA0 | `FUNC_ADDR` | `funcIdx:u16` | 压该函数入口的**模块内绝对地址**（配 `JMP_IND`/`CALL_IND`） |

### 4.13 线程（0xB0–0xBF）

进程内 `std::thread`，共享进程内存（线程各有自己的数据栈/作用域栈/帧栈）。

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0xB0 | `THREAD_SPAWN` | `funcIdx:u16, argOff:u32, tidOutOff:u32` | 起线程跑该函数（参数按目录 argSize 拷贝），tid 写槽 |
| 0xB1 | `THREAD_JOIN` | `tidOff:u32` | 等线程结束 |
| 0xB2 | `THREAD_EXIT` | — | 结束当前线程 |
| 0xB3 | `THREAD_SELF` | `outOff:u32` | 取当前 tid |
| 0xB4 | `THREAD_YIELD` | — | 让出 CPU |

跨线程同步用 `ATOMIC_*`；`GET_ADDRS` 可拿共享的 `Manager*`。

### 4.14 进程（0xC0–0xCF）

Linux `fork()`，**真地址空间隔离**。

| 编码 | 助记名 | 操作数 | 语义 |
|---|---|---|---|
| 0xC0 | `PROC_SPAWN` | `funcIdx:u16, argOff:u32` | fork 子进程跑该函数，父进程压 pid |
| 0xC1 | `PROC_WAIT` | `pidOff:u32, statusOff:u32` | waitpid，退出码写槽 |
| 0xC2 | `PROC_EXIT` | — | 弹 u64 退出码并 `_Exit` |
| 0xC3 | `PROC_SELF` | `outOff:u32` | 取 pid |
| 0xC4 | `PROC_SHARE` | `size:u64, outOff:u32` | `mmap(MAP_SHARED)` 共享内存（**fork 前**调用） |

## 5. 有符号 / 无符号：什么时候参数才真的生效

这是 v3 相对 v2 最需要说清的一点。**合并 ≠ 抹掉差异**：

| 运算 | 符号位生效？ | 原因 |
|---|---|---|
| `ADD` `SUB` `MUL` `NEG` | ❌ | 补码下位模式完全相同 |
| `SHL` `AND` `OR` `XOR` `NOT` | ❌ | 同上 |
| `CMP EQ` / `CMP NE` | ❌ | 逐位比较 |
| `DIV` `REM` | ✅ | `div` vs `idiv`，操作数还要先符号扩展 |
| `SHR` | ✅ | `shr`（逻辑）vs `sar`（算术） |
| `CMP LT/LE/GT/GE` | ✅ | `setb` vs `setl` |
| 加宽 `LOAD`/`STORE`、`CVT` | ✅ | `movzx` vs `movsx` |

所以合并并不是硬凑：**只在真的不同处读一下 bit2**，其余情况那个 bit 被忽略。
解释器与 JIT 都是这么做的。

## 6. v2 → v3 对照

| v2 | 条数 | v3 |
|---|---|---|
| `OP_ADD_U8/U16/U32/U64/F32/F64` | 6 | `ADD td` = 1 |
| `OP_SUB_*` | 6 | `SUB td` |
| `OP_MUL_*` | 10 | `MUL td` |
| `OP_DIV_*` | 10 | `DIV td` |
| `OP_SQRT_*` / `OP_LOG_*` | 10 + 10 | `SQRT td` / `LOG td` |
| `OP_SHL_*` + `OP_SHR_*` | 4 + 8 | `SHL td` / `SHR td` |
| `OP_AND_*` / `OP_OR_*` / `OP_NOT_*` | 4 + 4 + 4 | 各 1 条 |
| `OP_CMP_LT/EQ/GT × 11` | 33 | `CMP sub,td` = 1（且多了 LE/NE/GE） |
| `OP_CVT_*` | 8 | `CVT src,dst` |
| `OP_REG_MOVI/PUSH/POP/LOAD/STORE × 4` | 20 | 各 1 条 + TD |
| `OP_ADD_PTR` / `OP_SUB_PTR` | 2 | `ADD/SUB td=TD_PTR` |
| `OP_ATOMIC_*_U32` + `_U64` | 10 | 各 1 条 + TD |
| `OP_MOVI_U32` | 1 | `PUSH_IMM td` |
| `OP_END` / `OP_SHORT_JMP` / `OP_IF_GOTO` | 3 | `HALT` / 用 `JMP`+`BRANCH` |
| — | **+13** | `JIT_SUBMIT` `JIT_COMPILE` `CALL_NATIVE` 等原生支持指令 |
| **177** | | **68** |

## 7. 性能相关的说明

同机实测，便于判断「合并类型」有没有代价：

| 场景 | 数字 |
|---|---|
| 解释器执行一条 VM 指令 | ≈ 13.6 ns |
| JIT 编译一条 VM 指令（copy-and-patch） | ≈ 165 ns |
| JIT 编译一个函数（边际成本） | ≈ 3.3 µs（冷启动 ~25 µs） |
| 摊薄点（JIT 多久回本） | ≈ 19 轮循环 |
| 热循环 JIT vs 解释器 | 11.7 ns/轮 vs ~190 ns/轮（**16×**） |

**编译一个函数的代价 ≈ 解释执行它 19 轮循环**，而循环通常是百万轮级别。

合并导致的唯一运行时开销是**多读 1 个字节的 TD**，以及解释器里一次
「TD → 特化类型」的分派；JIT 里连这次分派都没有（模板是编译期特化好的）。
