# JadeightCompiler (j8c) 使用指南

面向 JadeightAbstractionCode 的 C 风格编译器：`.j8` 源码 → Jadeight 汇编 → **ISA v3 模块 `.bc`**，
由 `j8run` 在 Jadeight2ReWrite 的 VM 上运行（解释器，或 `--jit` 走 copy-and-patch 模板 JIT）。
支持面向协议、ECS、泛型，以及循环展开/常量折叠等优化。

> 指令集与模块格式的唯一事实源是 `../Jadeight2ReWrite/isa.hpp`（opcode 68 条、`TypeDesc`、
> `ModuleImage`）；指令逐条说明见 [06-指令集参考.md](06-指令集参考.md)，JIT 见 [14-JIT.md](14-JIT.md)。

## 构建

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target j8c j8run -j4
```

产物：`build/j8c`（编译器）、`build/j8run`（VM 运行器）。

依赖：C++20、`libffi`（`pkg-config libffi`，j8run 用它做 `EXTERN_CALL`）、`Threads`；
编译期还需要兄弟工程的 `../Jadeight2ReWrite/isa.hpp` 与 `../JadeightAbstractionCode/jadeight_asm.hpp`
（CMakeLists 通过 `JADEIGHT_VM_DIR` / `JADEIGHT_ASM_DIR` 加进 include 路径）。

## 用法

```bash
./build/j8c 源文件.j8 [-o out.bc] [-S] [-O0|-O1|-O2] [--no-unroll] [--unroll-limit N] \
                      [--ecs-capacity N] [--stack N] [-emit-externs manifest.txt] [-v] [--dump-ast]
./build/j8run out.bc [--externs manifest.txt] [--lib lib.so]... [--threads N] [--jit]
```

| 选项 | 说明 |
|---|---|
| `-o out.bc` | 输出路径；不给就把输入文件的扩展名换成 `.bc` |
| `-S` | 保留生成的 `.jasm` 汇编文本（与 `.bc` 同目录同名） |
| `-O0` / `-O1` / `-O2` | 优化级别，**默认 `-O2`** |
| `--no-unroll` | 禁用循环展开 |
| `--unroll-limit N` | 全展开的迭代次数上限（默认 8） |
| `--no-inline` | 禁用内联（当前版本没有内联实现，仅为兼容保留） |
| `--ecs-capacity N` | ECS 世界实体容量（默认 4096） |
| `--stack N` | 覆盖栈大小（字节，默认按程序自动计算） |
| `-emit-externs f` | 输出外部函数清单（供 `j8run --externs` 注册） |
| `-v` / `--verbose` | 详细输出：函数数、入口下标、码流大小、栈大小等 |
| `--dump-ast` | 打印顶层声明（AST 摘要） |
| `-h` / `--help` | 帮助（返回 0） |

产物格式：

- `.bc` 是 **ISA v3 模块**（全小端）：magic `"J3BC"`(4B) + u32 version(=3) + u32 funcCount +
  u32 codeSize + u32 entryFunc + funcCount × 20B `{offset,size,argSize,retSize,entry}` + 码流。
  入口函数下标在模块头里（`main` 不一定是 0 号函数）。定义见 `isa.hpp` 的 `ModuleImage`。
- 外部函数清单每行一条：`name:rettype(arg1,arg2,...)`，指针类型统一归一化成 `ptr`。
- `-S` 留下的 `.jasm` 是**可再汇编的**文本（同样的函数划分、函数相对标签），
  `jasm out.jasm -o out.bc` 能编回等价模块。

运行：

```bash
./build/j8run out.bc              # 解释器
./build/j8run out.bc --jit        # 模板 JIT；某个函数不支持就自动回退解释器（见 14-JIT.md）
./build/j8run out.bc --threads 4  # SPMD：N 个线程跑同一份字节码（配合 tid/atomic_* 内建）
./build/j8run out.bc --externs lib/externs.txt --lib ./lib/tp.so
```

`j8run` 的第一行 `===== j8run: <路径> =====` 是横幅，走 stdout；脚本里比对输出时用
`tail -n +2` 丢掉它（`tests/run_tests.sh` 就是这么做的）。

## 快速示例

```c
void main() {
    u32 a = 1 + 2 * 3;
    print(a);                     // 7
    u8 c = 65;
    print(c);                     // 65
    print(10);                    // 10
}
```

```bash
./build/j8c demo.j8 -o demo.bc -O0 && ./build/j8run demo.bc
```

递归与栈：

```c
u32 fib(u32 n) {                  // 递归：斐波那契
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}
void main() {
    print(fib(20));               // 6765
    print(fib(25));               // 75025（深递归，验证栈）
}
```

（以上两段示例的输出已在 `-O0`/`-O2`、解释器与 `--jit` 四种组合下实测一致。）

协议/ECS/泛型示例见 `tests/t4_protocol.j8`、`tests/t5_ecs.j8` 与 07 语言参考。

## 语言要点（速记）

- **语言完整手册见 [07-语言参考.md](07-语言参考.md)**；
  这里只列最容易踩的几条：
- 整数字面量默认无符号：`0 - 7` 按 u32 回绕；要负数写 `-7` 或显式 `i32`。
- `x * y;` 形式会被解析为指针变量声明（与 C 的 typedef 消歧同理）。
- 参数一律**按值传递**；返回类型 `u8/u16/u32/u64`、`i32/i64`、`f64`、`void`。
- 函数先定义后调用；`main` 为程序入口，`void main()`。
- 支持的优化：常量折叠、常量传播、循环展开（`#pragma unroll`）、DCE、强度削减。
- **`print` 的输出粒度**（实测，注意别被示例注释误导）：
  `u8`/`u16`/`u32` 按一行一个数打印；
  而 `u64`、有符号、浮点以及**字符串字面量**都是**逐字符输出、每个字符占一行**
  （`print(3.5)` 得到 `3\n.\n5\n0\n0\n`；`print("big")` 得到 `b\ni\ng\n`，
  见 `tests/t6_fold.expected` 与 `tests/t2_control.expected`）。
  这是当前实现的既有行为，是否为预期设计**待确认**。

## 测试

```bash
tests/run_tests.sh
```

- 对 `tests/t*.j8` 每个用例在 `-O0` 与 `-O2` 下编译运行，输出与同名 `.expected` 逐行比对；
  用例目录里存在 `tests/<名>.threads` 时，其中的数字会作为 `j8run --threads` 参数传入。
- 当前共 **9 个用例**：`t2_control`、`t3_functions`、`t4_protocol`、`t5_ecs`、`t6_fold`、
  `t7_unroll`、`t8_pointers`、`t9_ecs_run`、`t10_atomic` —— 即 **9 × 2 = 18 项**。
- 本次核对实测：解释器 **18/18 通过**，`--jit` 同样 **18/18 通过**。
- `run_tests.sh` 本身只跑解释器；`--jit` 需要另跑一遍：

```bash
# --jit 回归（脚本未内置）
for src in tests/t*.j8; do
  base=$(basename "$src" .j8)
  for opt in 0 2; do
    ./build/j8c "$src" -o "/tmp/$base.bc" -O$opt
    args=(); [ -f "tests/$base.threads" ] && args=(--threads "$(head -1 "tests/$base.threads")")
    ./build/j8run "/tmp/$base.bc" --jit "${args[@]}" | tail -n +2 | diff - "tests/$base.expected" >/dev/null \
      && echo "ok   $base -O$opt" || echo "FAIL $base -O$opt"
  done
done
```

`run_tests.sh` 的注释与 README 把 `-O2` 标为实验性/不稳定，`-O0` 为可信基线；
不过当前 9 个用例在两个级别下都通过。

## 版本历史

- 迁移到 **ISA v3**：`j8c` 的目标指令集改为 `Jadeight2ReWrite/isa.hpp`（68 条合并式 opcode），
  产物从旧的单函数字节码改为 **v3 模块**（magic `"J3BC"`）；中间仍复用 `jadeight_asm` 汇编层。
- 新增 `j8run --jit` 运行路径：copy-and-patch 模板 JIT，不支持的函数自动回退解释器（见 14-JIT.md）。
- 多线程原子指令支持，新增 `t10_atomic` 测试（18/18 全绿）。
- 新增 `t9_ecs_run`：覆盖 `run<System>()` 的边界（空 world、组件过滤、run 中 spawn 的 count 快照、
  嵌套 run、run 中 despawn、remove 后不再处理、批量遍历）。
- 实现 `run<System>()` 系统分发。
